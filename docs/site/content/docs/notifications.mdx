---
title: Notifications & Inbox
---

Orca runs agents, not just terminals, so it knows when an agent actually finishes versus when it's just paused. Notifications lean on that signal so you can queue three agents, walk away, and come back when the first one is done.

## Agent-finished pings

An agent's new done, input-needed, or blocked transition can play its selected sound at any session priority, even when Orca is focused or the OS banner is suppressed. Desktop agent banners appear only for sessions whose effective priority is P4 or above, after the Activity **Work** switch shifts work projects; unassigned sessions default to P3. Existing in-app unread attention and mobile delivery do not depend on this banner threshold.

## Persistent bell

The header bell shows unread notifications across all worktrees. Clicking a notification jumps to the matching worktree and pane.

On macOS, the same unread count is mirrored as a badge on the Dock icon, so you can spot pending agent pings without bringing Orca to the foreground.

## Mark unread

Right-click a notification to mark unread — useful when you've triaged something but want to come back to it later.

## Tuning

Use [Settings → Notifications](/docs/settings) to enable or disable desktop notifications and agent or terminal-bell sources. Focus suppression applies to banners, not sounds.

## Custom sounds

Choose a sound and volume independently for Done, Needs input, and Failed / blocked under [Settings → Notifications](/docs/settings). Select a built-in sound or an audio file on disk (MP3, WAV, OGG, M4A, AAC, FLAC). The Done selection also applies to terminal bells. For agent alerts, System Default plays Orca's built-in Two Tone so it can sound even when no banner appears. Test notifications and terminal bells retain the platform's OS-default sound behavior.

## Disable mobile push from a host

Set `ORCA_MOBILE_PUSH_MODE` in the environment of each desktop or remote runtime
that sends mobile push, then restart that host:

- `full` (default): existing notification titles, bodies and navigation identifiers.
- `disabled`: no alert or test sends and no new push registration from that host.
  Existing registration deletion and queued cleanup still run. This does not
  itself erase historical gateway/provider records or disable live in-app events.

An unrecognized nonempty value disables push delivery. This is a host configuration,
not a centrally enforced organization policy. Users who control the host environment
can change it. It applies to that host's push gateway traffic, not local desktop
notifications or direct/Relay application content. Every sending host needs the
setting; older Orca versions do not implement it. OS notification permissions and
lock-screen preview settings are separate controls.

There is no generic-content mode: enabled push may include project/agent text and
identifiers. Disabling phone lock-screen previews does not stop that content from
reaching the push gateway and APNs/FCM.
